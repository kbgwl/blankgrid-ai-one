# 空白格 · AI 控制台(BlankGrid AI One)

> 一人,一格,一军。每个空白格里,住着一位 AI。
> 无锡空白格人工智能科技有限公司

AI 即一家公司:创始人只下达目标,CEO Agent 统观全局并把目标拆成部门工作流,部门负责人拆成交付物,团队执行、评审不过就返工,合格成果自动归档。组织架构即界面,每个岗位是一枚发光的格子,实时看到谁在做什么、产出如何。

## 环境准备(首次一次)

仓库不含 `tools/`(数百 MB,已被 `.gitignore` 排除),本地工具链需自己放好:

```
tools/
  jdk-17/                  Temurin JDK 17 (Adoptium)
  apache-maven-3.9.9/
  maven-settings.xml       把中央仓库指向阿里云镜像
  env.bat / env.sh         把上面两者临时注入 PATH,不动系统环境
```

- JDK:https://mirrors.tuna.tsinghua.edu.cn/Adoptium/17/jdk/x64/windows/ (取 `OpenJDK17U-jdk_x64_windows_hotspot_*.zip`)
- Maven:https://mirrors.huaweicloud.com/apache/maven/maven-3/3.9.9/binaries/apache-maven-3.9.9-bin.zip

解压后确认 `tools\jdk-17\bin\java.exe` 与 `tools\apache-maven-3.9.9\bin\mvn.cmd` 都在,脚本会自动接管;目录名不同则改 `env.bat` 里的两处路径。Node 22 需系统已安装(`tools\node` 存在时也会优先用)。

## 快速启动

**开发模式**(前后端热更新,改代码用):双击 `start.bat`,浏览器自动打开 http://localhost:5180

**生产模式**(单进程,上线/日常使用用):
1. 双击 `build-prod.bat` 构建一次(前端 dist + 后端 jar)
2. 之后双击 `start-prod.bat`,浏览器打开 http://localhost:8090

> 生产模式数据目录为项目根的 `data/`;开发模式为 `backend/data/`。两边数据不互通,建议日常固定用一种。

手动启动:

```bat
:: 后端(8090) —— 先 call 环境脚本,mvn 才会在 PATH 里
call tools\env.bat
cd backend
mvn spring-boot:run

:: 前端(5180),另开一个窗口
cd frontend
npm run dev
```

## 第一次使用

1. 打开 **设置** → 填写大模型服务商(OpenAI 兼容协议,兼容智谱 GLM / OpenAI / DeepSeek 等):
   - Base URL,如 `https://open.bigmodel.cn/api/paas/v4`
   - API Key、默认模型(如 `glm-4.6`)
   - 按需设定「质量与目标引擎」的评审通过分、单件返工轮次与自动拆解
2. 打开 **目标** 页,写下一个公司目标(可补充背景、成功标准、截止时间与 token 预算)。
3. CEO 自动拆解 → 部门负责人拆交付物 → 团队执行 → 评审/返工 → 成果入库;在项目详情里看进度与每条交付,在 **成果** 页检索与下载。
4. 如果项目页出现「需要你补」的面板:写清那些公司查不到的事实(功能清单、真实数据、价格),提交后受阻的交付会立刻重新排队。
5. 想拿到可直接使用的文件:在 **设置 → 成果落盘** 指定目录,之后的成果会自动写成 md;也可在项目页、成果库点「导出」选 **Word / PDF / PPT** 直接下载,或「存到目录」一次写全四种格式。PDF 会嵌入系统中文字体,不用装 Office 也能打开。

## 功能

- **目标生产线**:目标 → 部门工作流 → 交付物 → 执行 → 评审 → 返工 → 成果归档;支持暂停/恢复、单件重试、完成后再返工、整项目 ZIP 导出或直接落盘。
- **缺料上报**:CEO / 部门负责人 / 评审遇到「必须核实的外部事实」(产品功能名、真实客户数、价格、资质)时,不再硬编,而是列进目标的**待补清单**;你在项目页填一次事实,后续拆解、执行、评审全程以它为准,受阻交付自动重新排队。可假设的(文风、篇幅、结构)仍按假设推进并写进 brief。待补清单按**主题收敛**:产品事实、客户案例、联系方式、品牌资产、域名托管、ICP 备案、表单服务各问一次,不会出现三个人各问一遍「你的产品叫什么」。
- **落盘目录**:成果不只存数据库。设置页可指定目录(留空 = 程序目录下 `exports/`),通过评审的成果自动写成 `README.md + plan.md + manifest.json + artifacts/*.md`,目标文件夹形如 `001-目标标题/`;也可在成果库、项目页手动落盘单份。
- **多格式导出**:同一份成果可以出 **Markdown / Word(.docx)/ PDF / PPT(.pptx)**。整本项目能合成一本(`项目成果.docx` / `项目成果.pdf`)或一份汇报稿(`项目汇报.pptx`)。纯 Java 生成(POI + OpenPDF),不依赖本机装 Office / LibreOffice;PDF 自动嵌入系统中文字体(Windows 找微软雅黑/黑体,Linux 找 Noto CJK),设置页可指定字体文件。
- **成本核算**:token 账本记账时一并记下模型名,按设置里的单价表(元 / 百万 token)折算成钱,指挥台、项目卡、项目详情、设置页都显示「今天花了多少」而不是「烧了多少 token」。单价表可改,默认按输入:输出 = 3:1 折算,量级估算而非对账单。
- **密钥加密落盘**:`settings.json` 里的 API Key 与访问口令以 AES-256-GCM 密文保存(每次加密随机 IV),主密钥取环境变量 `AIONE_SECRET`,没有就在 `data/.secret.key` 生成 32 字节随机密钥。老版本明文配置在启动时自动迁移为密文,内存里仍是明文(否则调不通模型)。挡住的是「文件被单独拷走 / 误提交 / 进了备份包」。
- **拆解粒度闸门**:除了提示词明确禁止,落库前还有一道确定性判定 —— 标题含「规格/规范/台账/清单/核算/口径/字典/明细/对照表」且不含成品词(文案/方案/报告/页面/设计/代码/手册…)且标题不长,就判为**附属物**,并进同一责任人的成品里当章节或附表,不再单独占一条生产线。实测过的「字体层级规格」「token 用量核算表」「指标口径字典」都会被拦下。
- **结构化输出兜底**:拆解、评审这类必须吐 JSON 的调用,走服务端 `response_format: json_object` 强制 JSON,输出上限从默认 4K 提到 8K(中文长清单写到一半被切断,表现就是「不是有效 JSON」)。真遇到坏格式还有两层:`LooseJson` 本地修复(围栏、前后解说、截断补括号、尾逗号、全角引号),救不回来再把原样丢回模型自修一次;仍失败才报错,并把原始输出存到 `data/diagnose/` 便于追查。服务商若不支持 `response_format` / `max_tokens`,自动去掉该字段重发,不会因此整段停摆。
- **欠费/限流不停摆**:服务商侧失败(402 余额不足、429 限流、超时、空响应)与"活干砸了"分开处理 —— 前者不扣重试次数,交付物退回待执行而不是判死;连续遇到就拉起**全局闸门**,停掉调度并在页面顶部弹出横幅说明原因,不让几十条交付物挨个刷成失败。充值后在设置页点一次测试连通即恢复,不用重启。**重启也会自愈**:上次运行中中断的任务在启动时标记为中断,对应交付物直接回队列(不消耗重试次数);整目标受阻可用项目页「重试受阻」一键推回。
- **依赖传导**:上游交付受阻时,下游进入「等上游」而不是带着空上下文硬写,上游恢复后自动重新排队。
- **不重复开工**:同一件事只由一个部门负责。部门拆活时既有提示词约束(把其他部门已在做的清单直接摆给负责人),落库前还有一道确定性查重(标题归一化后比对),重复项自动并入已有交付物,依赖也跟着指向真正承担它的那一项。
- **并发上限**:设置页的「并发执行数」真正生效,同一时刻只有这么多交付物在跑,其余排队等空位(不限制会同时打出十几个请求,撞上服务商限流后全部失败重试,比串行更慢也更贵)。
- **人工接管**:成果正文可以直接改(项目页抽屉、成果库都能编辑),改过的标为「人工修订」;改完可「定为最终版」,对应交付物直接置为完成,下游等待自动解除。评审不过时不必只能整轮重跑模型。
- **预算可见**:token 用尽时目标自动暂停并上报;项目页出现红色横幅,可一键追加额度,追加后自动恢复,不用再点一次「恢复」。
- **指挥台**:写下目标即开工;目标卡展示部门、进度、成果数、评审均分与 token 消耗。
- **组织架构**:CEO 统观全局、部门负责人、执行岗位三层;每个部门负责人置顶并标注,支持新建部门、添加岗位、调整层级/部门/汇报关系,新部门自动补齐负责人。执行中呼吸光晕、连线流光、出错赤色脉冲、完成涟漪。
- **任务系统**:任务按岗位排队执行,流式输出实时显示;任务可附带其他岗位的产出作为输入,实现协作(如产品经理的 PRD → 开发工程师)。
- **看板**:顶部状态条(在跑 / 待办 / 待处理 / 成果 / token)+ 在办目标进度 + 等你拍板 + 待处理/执行中/完成/失败四列任务流 + 实时动态。
- **成果库**:按状态/项目/关键词检索,查看评审意见与 Markdown 正文,单篇下载、存到落盘目录或随项目打包导出。
- **设置**:多 LLM 服务商配置(密钥只存本机 `settings.json`,接口返回自动掩码)、**模型名可从服务商拉取成下拉**(手敲模型名写错会让整条生产线 400)、公司质量准则、落盘目录与自动落盘、访问口令、自动备份与**恢复**(运行中只暂存,重启时在 JPA 打开连接前替换,原库另存一份可回退)。

## 技术栈

- 后端:Spring Boot 3 + JPA + H2(本地文件库 `backend/data/`)+ WebSocket(STOMP)
- 前端:Vue 3 + Vite + Element Plus + SVG 自绘架构图
- 工具链:JDK 17 与 Maven 3.9.9 随项目放在 `tools/`,由 `env.bat` 临时注入 PATH,不污染系统;Node 22 用系统安装

## 质量保障

- 单元测试 66 例:`LooseJsonTest`(模型输出坏掉的七种典型:` ```json ` 围栏、前后夹解说、被 max_tokens 截断、缺右括号、多尾逗号、全角引号当键、字符串里裸换行)、`NeedsInputTopicTest`(待补清单按主题收敛:产品事实/客户案例/域名/备案/表单各问一次,「表单接收邮箱」不会被当成联系方式吞掉)、`ProviderErrorTest`(分清"活干砸了"和"服务商欠费/限流/超时",后者不该扣重试次数)、`DeliverableDedupTest`(查重口径,含实跑撞到的重复案例)、`DeliverableGuardTest`(附属台账判定:该拦的拦、成品不误杀、长标题豁免)、`DocExportServiceTest`(三种格式的文件头、中文能读回、PDF 嵌入字体与 ToUnicode)、`SecretBoxTest`(加解密往返、随机 IV、换密钥解不开时返回空而不是乱码、落盘文件无明文 Key)、`GoalServiceBudgetTest`(追加预算的恢复语义)、`SettingsServiceTest`(默认值/密钥掩码/部分更新语义/决策槽位回退)、`LlmServiceTest`(自检失败分支,并断言错误信息不回显密钥)
- `mvn package` 会在打包前跑完全部测试;CI 见 `.github/workflows/ci.yml`(后端 JDK 17 打包 + 前端 Node 22 构建)

## 容器化

```bash
docker build -t aione .
docker run -p 8090:8090 -v aione-data:/app/data aione
```

镜像内前端构建产物放在 `/app/frontend/dist`,由后端单进程托管。`data/`(H2 库 + `settings.json` 含密钥)必须挂卷,否则重建容器就丢。

## 部署

- 配置全部外置(`application.yml` / 环境变量),API Key 不入库;落盘的 `settings.json` 里是密文
- 主密钥优先取 `AIONE_SECRET` 环境变量(适合容器 / 多机):`docker run -e AIONE_SECRET=... `;不给就落到 `data/.secret.key`,**换机器要连这个文件一起带**,否则原 Key 解不开,需要在设置页重填一次
- PDF 导出需要中文字体:镜像里已装 `fonts-noto-cjk`;裸机部署时 Windows 自带即可,精简版 Linux 需装 `fonts-noto-cjk` 或在设置页指定字体文件路径
- H2 → MySQL 只改 `spring.datasource.url`
- 前端 `npm run build` 产出 `dist/` 可静态部署,后端可独立部署
- 换机器时:`tools/` 不在仓库里,按「环境准备」重新放一份,或直接用上面的 Docker 镜像,不需要本地工具链
